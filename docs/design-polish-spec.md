# Design Polish — the one-click "make it better" pass

**Status: RATIFIED 2026-07-27** (client ruling, verbatim): "when i am done designing / dont know how to make it better, i want to be able to prompt the ai to help me clean up / improve my design, and ai will adjust my composition of elements, or remove unnecessary shapes and accessories, make sure accessibility. Currently ai cannot do that one click improvement."

Subordinate to the DLC (AI proposes → schema/policy validate → typed commands → render → verify → narrate; §4) and the advice-ledger law — with one deliberate carve-out: the ledger's "nothing auto-applies from the auditor" protects users from UNINVITED changes; a Polish invocation IS the invitation. Tapping Polish is consent (the "Move it anyway" precedent generalized).

## The gesture

- A **"Polish my design"** action: a button near Export/readiness AND chat phrases ("clean this up", "improve my design", "make it better", "polish") routed by a deterministic belt.
- One tap → the full pass runs → ONE honest summary reply listing exactly what changed and why ("Tightened the composition, removed 2 decorative shapes that crowded the photo, flipped the support ink for contrast") — every claim changedPaths-backed. **One undo restores everything.**

## What the pass does (in order, each stage through existing machinery)

1. **Deterministic repair, full strength:** the harmonizer's fail-severity fixes + the contrast/accessibility ladder across every text role/element and the logo (all formats, not just active). Accessibility is non-negotiable: after Polish, every painted text meets its floor or carries the honest over-capacity advisory.
2. **De-clutter:** decoration/shape budget enforcement — remove or scale back added decor that exceeds the layout's density/area budget or collides with content, LOWEST visual value first (smallest contribution, most collisions). Never removes the media host or content. Each removal named in the summary.
3. **Composition re-solve:** re-run placement for system-owned variables (spacing, balance, alignment to the layout's zones) honoring the hierarchy law. Pinned placements MAY be adjusted by Polish (the tap is consent) but every pin change is NAMED in the summary; pins the pass didn't need to touch stay untouched.
4. **AI art-direction pass (paid, one call):** the existing design-audit route judges the polished state on its subjective dimensions; its constrained enum fixes are APPLIED (not just suggested) when they pass schema/policy validation — this is the carve-out; the audit's suggestions remain suggestions in every other flow.
5. **Verification:** render truth confirms every claimed change; readiness recomputes; if the pass made nothing better (no findings, no over-budget decor), the reply says so honestly ("This already reads clean — nothing I'd change") — never a placebo change.

## Rules

- Runs through the same typed-command/patch grammar as every other actor. No new mutation paths.
- One Polish = one undo transaction = one honest summary. No silent residue.
- Money: stage 4 is a real model call — Polish is a user-invoked paid action (same class as photo generation); tests mock it and stages 1-3 remain fully functional without a key (Polish degrades gracefully to the deterministic pass with an honest note).
- Born-clean interplay: fresh generations should have nothing for Polish to do — a Polish on an untouched fresh design finding real fixes is a generation-quality bug signal (log it via the feedback capture).

## Verification bar

- Unit: stage ordering, pin-change disclosure, one-undo transaction, placebo-guard (no-op honesty), degraded no-key path.
- Live: a deliberately messy design (3 excess shapes, low-contrast pinned ink, crowded elements) → one tap → measurably cleaner (decor within budget, all contrast floors met, hierarchy holds), summary lists every change, one undo restores the mess exactly. A clean design → honest "nothing to change."
- Battery: born-clean/arch-stress/fingerprint unchanged (Polish is an action path, not a render change).
